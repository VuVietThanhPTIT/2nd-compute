| Khái niệm / Thành phần | Bản chất & Chức năng |
| --- | --- |
| **NetApp** | Tập đoàn công nghệ đa quốc gia của Mỹ, chuyên cung cấp các giải pháp quản trị dữ liệu, hệ thống lưu trữ doanh nghiệp (*Enterprise Storage*) và điện toán đám mây kết hợp (*Hybrid Cloud*). Cung cấp: Hệ điều hành ONTAP (lưu trữ), Thiết bị lưu trữ phần cứng, Quản trị dữ liệu đa đám mây (*Data Fabric*), Công nghệ chống trùng lặp & Snapshot $\rightarrow$ Hệ sinh thái lưu trữ. |
| **VFS (Virtual File System)** | Tầng trừu tượng hóa của Linux giúp đồng nhất mọi hệ thống tệp (`ext4`, `xfs`, `btrfs`, `NFS`) thành một giao diện hàm chung (`open`, `read`, `write`). |
| **Block Layer (`blk-mq`)** | Tầng trung gian trong Linux quản lý việc gom cụm, xếp thứ tự và điều phối các yêu cầu khối xuống đĩa thông qua kiến trúc đa hàng đợi (*Multi-Queue*). |
| **DMA (Direct Memory Access)** | Tính năng phần cứng cho phép thiết bị ngoại vi (NVMe SSD, Card mạng) tự đọc/ghi trực tiếp vào RAM mà CPU không cần bốc vác từng byte. |
| **IOVA / DMA Address** | Địa chỉ bộ nhớ theo góc nhìn của thiết bị ngoại vi trên bus truyền dẫn (PCIe), được ánh xạ qua phần cứng IOMMU. |
| **Virtqueue** | Cấu trúc dạng vòng tròn (*Ring Buffer*) trên RAM chia sẻ giữa Guest VM và Host, đóng vai trò "bảng giao việc" I/O giữa driver `virtio-blk` của Guest và backend xử lý phía Host. |
| **vhost-user-blk** | Giao thức cho phép backend block (như SPDK) chạy ở User Space của Host, đọc trực tiếp Virtqueue trên bộ nhớ chia sẻ (*Hugepages*) thay vì để QEMU làm backend. |
| **irqfd** | Cơ chế của KVM để backend kích hoạt ngắt ảo (*Virtual Interrupt*) đánh thức vCPU của Guest khi I/O hoàn tất. |
| **SPDK** | *Storage Performance Development Kit*: Bộ framework mã nguồn mở chạy hoàn toàn ở User Space, tối ưu hóa I/O bằng cơ chế Polling, Lockless và Kernel Bypass. |
| **/dev** | Chứa device node — điểm truy cập thiết bị do kernel cung cấp. `/dev/`: Thư mục chứa các file đặc biệt (device nodes) do kernel và `udev` (hoặc `devtmpfs`) tạo ra để làm giao diện giao tiếp giữa user-space và driver trong kernel.<br><br>**d/sd/nvm (VirtIO Disk):** Viết tắt của thiết bị lưu trữ dùng chuẩn bán ảo hóa VirtIO Block (`virtio_blk`). Khác với `sd` (SCSI, SATA, USB drive thông thường) hay `nvme` (NVMe PCIe SSD), tiền tố `vd` chỉ xuất hiện khi hệ điều hành đang chạy trong môi trường ảo hóa (KVM, QEMU, Proxmox, AWS, OpenStack...).<br><br>**a/b/c/...: Định danh thứ tự của ổ đĩa theo bảng chữ cái:**<br>• `vda`: Ổ đĩa ảo thứ nhất (thường là ổ chứa hệ điều hành / root disk).<br>• `vdb`: Ổ đĩa ảo thứ hai (thường là ổ dữ liệu gắn thêm - Data Disk).<br>• `vdc`, `vdd`: Các ổ tiếp theo. |
| | Thanh RAM vật lý không có phân vùng riêng, không có chip riêng, và phần cứng bán dẫn không hề phân biệt đâu là dữ liệu Stack hay dữ liệu Heap. Tất cả chỉ là những tụ điện (DRAM cell) lưu bit 0 và 1. Trên thanh RAM vật lý: Một mớ hỗn độn các "Khung trang" (Page Frames). |
| **fio (Flexible I/O Tester)** | Là công cụ chuẩn công nghiệp trên Linux dùng để đo lường, kiểm thử hiệu năng và chịu tải (stress test) của hệ thống lưu trữ. Đo đạc 3 chỉ số I/O chính, Mô phỏng chính xác các loại tải, Can thiệp sâu vào luồng I/O (Bỏ qua Page Cache, Tùy chỉnh Queue Depth (iodepth)).<br><br>Tóm lại, nếu dd chỉ là công cụ copy file thô sơ thường bị Page Cache làm sai lệch kết quả, thì fio là công cụ đo đạc tiêu chuẩn phản ánh năng lực I/O thực tế của ổ đĩa và block layer. |
| **SPDK** | *Storage Performance Development Kit*: Bộ framework mã nguồn mở chạy hoàn toàn ở User Space, tối ưu hóa I/O bằng cơ chế Polling, Lockless và Kernel Bypass.<br><br>Nói "Lockless bdev Layer" nghĩa là:<br>+ SPDK phân chia ổ đĩa thành các kênh I/O độc lập cho từng CPU Core. Mỗi Core tự làm việc trên sân nhà của mình từ lúc nhận lệnh của VM cho đến lúc đẩy ra card mạng, không dùng chung hàng đợi, không dùng chung bộ đệm, và không có bất kỳ lệnh khóa (lock) nào cản đường dữ liệu. Điều này giúp hệ thống đạt hàng triệu IOPS mà độ trễ P99 vẫn phẳng lì.<br><br>NVMe là một chuẩn giao thức truyền thông (protocol specification), không phải một tiến trình phần mềm cố định. Do đó, bất kỳ đoạn code nào biết cách tuân thủ đúng định dạng lệnh NVMe (Command 64 bytes, Completion 16 bytes, cơ chế hàng đợi Submission/Completion Queue) và có quyền truy cập vào thanh ghi phần cứng đều có thể trở thành một driver NVMe — dù đoạn code đó chạy bên trong Kernel Space hay ở ngoài User Space. |
|IPC trung gian|  ở đây là cơ chế giao tiếp liên tiến trình (Inter-Process Communication) hoặc liên không gian (Kernel $\leftrightarrow$ User-Space communication) đóng vai trò làm cầu nối "bắn tín hiệu" qua lại giữa KVM (chạy ở Kernel) và QEMU / Backend (chạy ở User-Space) khi có thao tác I/O.<br> "IPC trung gian" ở đây chính là cơ chế gõ chuông báo hiệu (ioeventfd, irqfd) kết nối giữa nhân Linux (KVM) và tiến trình quản lý máy ảo (QEMU). Nó là giải pháp giúp hệ thống giao tiếp qua ranh giới Kernel-User, nhưng lại là điểm thắt cổ chai về độ trễ so với các giải pháp hiện đại bypass hoàn toàn cơ chế ngắt/báo hiệu này bằng kỹ thuật Polling trực tiếp trên RAM.|
